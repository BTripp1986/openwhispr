OpenWhispr - REVISION TEST BUILD (test only)
============================================

This is an unsigned, unpacked test build of a revised feature: every dictation
shortcut now carries its OWN text-cleanup setting, in one Dictation Hotkey
section. It is NOT an OpenWhispr release and is not signed, so Windows
SmartScreen will warn about it.

This REPLACES the October 14 test build's separate Raw Dictation and Cleaned
Dictation sections. Those are gone.

Your October 14 test build
--------------------------
This candidate runs on a DIFFERENT isolated channel ('staging'), so it starts
on a brand-new empty profile and cannot read, change or delete anything the
October 14 build owns. Nothing of yours is migrated, and nothing is wiped.

You will therefore set this build up from scratch - API key, shortcuts and
cleanup settings. That is deliberate: it is what keeps the earlier profile
intact. You do not need to uninstall or delete the October 14 build, and you
should not delete its profile unless you decide you want to.

What it will NOT touch
----------------------
* Your installed OpenWhispr. Nothing is installed or uninstalled; this build
  runs from the folder you unzipped.
* Your real OpenWhispr settings, history, notes or API keys. This build uses a
  separate profile: %APPDATA%\OpenWhispr-staging
  It also uses its own saved-credential entry (OpenWhispr-validation-staging),
  its own search index (qdrant-data-validation-staging) and its own CLI bridge
  entry (cli-bridge-staging.json).
* The October 14 test build's profile, credential entry and search index.
  Those end in -development / -validation and belong to that build; this one
  never opens them, including when you use Reset app data here.
* Your openwhispr:// links. This build registers openwhispr-staging:// instead.
* Your startup entry. This build's launch-at-login value name is distinct, and
  it is off unless you turn it on. Please leave it off.
* Updates. Update checks, downloads and installs are disabled in this build, so
  it can never replace your installed copy.
* Your downloaded speech and AI models. Those live in a cache this build
  SHARES with your install (%USERPROFILE%\.cache\openwhispr) so you do not have
  to re-download gigabytes. Sharing is not read-only - if you download a model
  inside this build it is written there, and your install can then use it too.
  What this build cannot do is remove or move them:
    - every "Delete model" / "Delete all models" button in this build refuses
      outright and tells you why;
    - "Reset app data" still erases THIS BUILD's own data (its settings,
      history, notes and saved keys in its own test profile) - that part works
      normally - but it keeps the shared model cache and says so;
    - it never relocates the cache.
  To actually delete a model, use your normal OpenWhispr install.

What is NOT sandboxed: your OpenWhispr cloud account
----------------------------------------------------
The separate profile isolates data on THIS PC. It does not sandbox anything
server-side. If you sign in, this build talks to the same real OpenWhispr
account as your normal install, and anything it syncs is your actual data.

"Delete account" is a permanent, server-side deletion of your real account -
not a local reset. This build refuses that one call so a stray click cannot
destroy your account, but do not rely on that: there is no reason to sign in
for this test at all.

So: run this test SIGNED OUT, using your own OpenAI key. The exact buttons:

  1. On the sign-in screen, click "Continue without an account".
  2. Work through the microphone and hotkey steps.
  3. On the setup screen, click "Show More Options", then choose
     "API Provider" ("Use your own API key.").
  4. Enter your OpenAI key there.

Then set BOTH halves of the pipeline in Settings - they are separate, and this
test needs both:

  - Settings -> "Speech to Text": provider OpenAI, and pick the transcription
    model.
  - Settings -> "AI Text Enhancement": the Dictation Cleanup scope, provider
    OpenAI, and pick the cleanup model and prompt. This is the extra pass that
    "Always on" forces and "Always off" skips.

How to run it
-------------
1. Quit your production OpenWhispr from its tray icon. Two copies cannot share
   the same global hotkeys. Quit the October 14 test build too if it is running.
2. Double-click Launch-OpenWhispr-Test.cmd
   (or Launch-OpenWhispr-Test-Debug.cmd to also write a debug log).
   Starting OpenWhispr.exe directly works too - the isolated profile is baked
   into the build, not set by the launcher - but the launchers print where that
   profile is.
3. SmartScreen: "More info" -> "Run anyway". It is unsigned on purpose.
4. Set up the test profile from scratch, following the signed-out steps above.
   Type the key into the app's masked field. Never paste a key into a chat, a
   log or a command line.

No Node, npm, git or build tools are needed.

What to actually test
---------------------
There is now ONE "Dictation Hotkey" section. Each shortcut in it is a row, and
each row has a "Customize cleanup" disclosure containing a "Text cleanup"
selector with three choices:

  Use app setting - follow your saved cleanup preference (the default, and what
                    every existing shortcut keeps).
  Always on       - always run the configured cleanup for this shortcut.
  Always off      - always skip the cleanup pass for this shortcut.

"Add another hotkey" adds more rows. Always on / Always off ignore the saved
preference without ever changing it.

What "Always off" means: it skips the optional AI cleanup pass. It is NOT a
promise of word-for-word output - the speech-to-text model may still tidy up
filler on its own. Judge it by whether the cleanup pass ran, not by how the
text reads. The debug log is decisive (see below).

Suggested run, with a disfluent sample like "um so like can you uh send the
thing to the team i guess":

  1. Settings -> Hotkeys -> Dictation Hotkey. Set up Ben's two rows:
       Ctrl+Shift+Space  -> Customize cleanup -> Always on
       Ctrl+Alt+Shift    -> Customize cleanup -> Always off
     Add the second with "Add another hotkey". Confirm a collapsed row with an
     override still shows which mode it is in.
  2. Turn your saved AI cleanup setting ON. Record once with each shortcut.
     Expect a cleanup request for Always on and none for Always off.
  3. Turn the saved setting OFF and repeat both. The two shortcuts must behave
     exactly as in step 2. This is the whole point of the feature, and the log
     is what proves it.
  4. After each one, reopen Settings and confirm your saved cleanup setting is
     exactly where you left it - using a shortcut must never change it, and
     neither must toggling it change either row's selector.
  5. Add a third row left on "Use app setting". It must follow the saved
     setting both ways, while the other two ignore it.
  6. Dictate something that sounds like talking to the assistant, e.g.
     "hey <your agent name> what is the weather". From an Always on or Always
     off row it must paste that as dictated text, NOT an assistant answer.
  7. Quit the test build, start it again, and confirm every row kept both its
     key AND its cleanup mode.
  8. Rename a row's shortcut to a different key. Its cleanup mode must follow
     the new key, not reset and not jump to another row.
  9. Remove a row. The remaining rows must keep their own modes - no override
     should move to a neighbour. Quit and restart: the removed row must stay
     removed, and must not come back.
 10. Try assigning a shortcut already used by another action (Voice Assistant,
     Translation, Meetings, or another row) - it should be refused with a
     message naming the conflict, not silently accepted.
 11. Activation mode (Tap / Hold) sits under the whole section and governs
     every row. With Hold selected, check that BOTH rows actually hold - press
     and keep held, speak, release to stop. If a row cannot support Hold, the
     control must say so rather than offering Hold and silently behaving as
     Tap. Then switch back to Tap and confirm both rows toggle again.
 12. Press one row, then the other about a quarter-second later. The second
     press must NOT be silently swallowed - it should stop the recording that
     the first one started. You must never end up with two recordings running
     at once.
 13. Change a row's Text cleanup selector while that row's shortcut is NOT in
     use. It should take effect immediately with no re-assignment, and the
     shortcut must still fire afterwards.
 14. Clear cleanup configuration (or pick no cleanup model) and record with an
     Always on row: you should still get your transcript pasted, plus a notice
     that cleanup did not run ("AI cleanup isn't set up"). It must not
     silently pass off the raw text as cleaned.
 15. Cancel a recording with Esc and immediately use another row; tap one row
     repeatedly; press another while the first is still processing. Nothing
     should paste twice, paste late, or come back in the wrong mode.
 16. Use "Reset to default" on the section. Say what it does to your rows and
     their modes - whatever it does, it should be consistent and should not
     leave a mode attached to a row you no longer have.
 17. Smoke-test that Voice Assistant, Translation and meeting/note recording
     still behave as before. Say so if any of them is unconfigured rather than
     counting it as passed.

How to read the decisive evidence: start from
Launch-OpenWhispr-Test-Debug.cmd and open the newest file in
%APPDATA%\OpenWhispr-staging\logs. Each recording logs one ROUTE_RESOLVED
line:
  Always off -> cleanupMode "raw",        cleanupSelected false, kind "skip"
  Always on  -> cleanupMode "cleaned",    cleanupSelected true,  kind "cleanup"
  app setting-> cleanupMode "preference", following your saved setting
An Always off recording shows no cleanup request after that line. Logs can
contain transcript text, so dictate synthetic phrases and skim a log before
sharing it.

What is missing compared to a release
------------------------------------
This artifact is built without any of the project's secrets, so:
* Google / Microsoft / Apple calendar, Slack, Linear and GitHub connectors
  report "not configured" and their Settings rows may be hidden. Expected.
* Signing in through a browser is not wired up on this channel. You do not need
  it - this test runs signed out.
* The licensed brand font is absent, so text renders in the bundled Noto Sans.
  Cosmetic only.
* It is unsigned, so the tray icon does not keep a fixed position.
Dictation, transcription and the AI cleanup pass - the things under test - are
unaffected.

When you are done
-----------------
1. Quit this build from its tray icon.
2. Start your production OpenWhispr and confirm its hotkeys, settings and
   history are unchanged.
3. To remove every trace of THIS build: delete the unzipped folder and
   %APPDATA%\OpenWhispr-staging. Optionally also delete
   %USERPROFILE%\.cache\openwhispr\qdrant-data-validation-staging,
   %USERPROFILE%\.openwhispr\cli-bridge-staging.json, the
   OpenWhispr-validation-staging entry in Windows Credential Manager, and the
   registry key HKEY_CURRENT_USER\Software\Classes\openwhispr-staging.

   Everything above ends in -staging. Leave the -development / -validation
   names alone unless you also want to remove the October 14 test build, and
   leave anything named OpenWhispr or openwhispr WITHOUT a suffix alone - that
   is your production install. Leave the model downloads in
   %USERPROFILE%\.cache\openwhispr alone too; both builds and your install
   share them.
